# فاز ۳ — چاپ، پیش‌نمایش و خروجی داده

**فاز ۳ از ۸.**

این فاز سؤال «آیا کاربر واقعاً چاپ گرفت یا فقط گزارش را دید؟» را می‌سنجد،
و خروج داده از سیستم را — که از نظر نشت اطلاعات مهم‌ترین دسته است.

---

## ⛔ یادآوری

1. فقط روی `YAZDSEPAR1405_TEST`. تأیید: `SELECT DB_NAME();`
2. کد را عوض نکن.
3. ⭐ **همه چیز با کلیک واقعی روی دکمه‌های برنامه.** فراخوانی مستقیم
   `Audit.Print` یا `Audit.Export` **ممنوع**.
4. حدس نزن، دروغ نگو.

```sql
SELECT MAX(LOG_ID) AS شروع_فاز۳ FROM dbo.SYS_AUDIT_EVENT;
```

# تست ۳.۱ — پیش‌نمایش در برابر چاپ واقعی

**چرا مهم است:** «باز کردن گزارش» با «چاپ گرفتن» یکی نیست. اگر هر دو یک
رویداد بسازند، نمی‌شود فهمید کاربر واقعاً کاغذ گرفته یا فقط نگاه کرده.

**با دست:**

1. یک سند را باز کن و **پیش‌نمایش چاپ** بگیر. پنجره‌ی گزارش را **ببند
   بدون اینکه چاپ کنی**.
2. حالا دوباره باز کن و این بار واقعاً **چاپ** کن (اگر چاپگر فیزیکی
   نداری، روی «Microsoft Print to PDF» چاپ کن — همان مسیر است).
3. یک گزارش دیگر باز کن و از داخلش **خروجی فایل** بگیر (PDF یا Word یا هر
   قالبی که Stimulsoft می‌دهد).

۳ ثانیه صبر کن:

```sql
SELECT LOG_ID, AT_SERVER, ACTION, CATEGORY, SEVERITY,
       ENTITY, ENTITY_KEY, FORM_NAME, TITLE
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID > <شروع_فاز۳> AND ACTION IN ('PREVIEW','PRINT','EXPORT')
ORDER BY LOG_ID;
```

**انتظار:**

| کار | `ACTION` | `SEVERITY` |
|---|---|---|
| پیش‌نمایش (بدون چاپ) | `PREVIEW` | ۱ (عادی) |
| چاپ واقعی | `PRINT` | ۲ (قابل‌توجه) |
| خروجی فایل از گزارش | `EXPORT` | ۳ (حساس) |

**مهم‌ترین بررسی:** آیا `TITLE` **نام واقعی گزارش** را دارد یا فقط نام کلاس
پنجره مثل `WINRPT`؟

> قبلاً فقط `WINRPT` ثبت می‌شد و معلوم نبود کدام گزارش چاپ شده. باید حالا
> عنوان واقعی گزارش (مثلاً «پیش‌فاکتور») در عنوان باشد.

❌ اگر پیش‌نمایش و چاپ **هر دو** یک `ACTION` ساختند، باگ است.
❌ اگر چاپ واقعی **هیچ** رویدادی نساخت، باگ جدی است.

# تست ۳.۲ — خروجی اکسل

**چرا مهم است:** با یک خروجی اکسل می‌شود کل یک لیست مشتری یا قیمت را از
نرم‌افزار بیرون برد. این حساس‌ترین نقطه‌ی نشت اطلاعات است.

**با دست:**

1. یک فرم که جدول دارد باز کن (مثلاً لیست مشتریان یا لیست کالاها).
2. روی دکمه‌ی **خروجی اکسل** کلیک کن.
3. تعداد ردیف‌های آن جدول را از خود فرم یادداشت کن.

```sql
SELECT LOG_ID, AT_SERVER, ACTION, SEVERITY, FORM_NAME, TITLE
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID > <شروع_فاز۳> AND ACTION = 'EXPORT' ORDER BY LOG_ID DESC;
```

**انتظار:**
- `ACTION = EXPORT`، `SEVERITY = 3`.
- `TITLE` باید **تعداد ردیف** را داشته باشد، مثل «خروجی Excel از … (۸۴۰ ردیف)».
- `FORM_NAME` باید نام **همان فرمی** باشد که از آن خروجی گرفتی.

عدد ردیفِ ثبت‌شده را با عددی که از فرم یادداشت کردی مقایسه کن. اگر
نمی‌خوانند، بنویس چقدر اختلاف دارند.

❌ اگر `FORM_NAME` خالی بود، بنویس — یعنی نام فرم از جدول استخراج نشده.

# تست ۳.۳ — چند فرم مختلف

این کار را روی **سه فرم متفاوت** تکرار کن (مثلاً لیست کالا، لیست مشتری،
یک گزارش مالی) و ببین هر سه ثبت می‌شوند و `FORM_NAME` هر کدام درست است.

> منطقش: خروجی اکسل از یک نقطه‌ی مرکزی می‌گذرد که حدود ۱۱۹ فرم از آن
> استفاده می‌کنند. اگر آن نقطه درست کار کند، همه پوشش دارند — ولی باید
> مطمئن شد نام فرم درست استخراج می‌شود.

جدولش را پر کن:

| فرم | ثبت شد؟ | `FORM_NAME` ثبت‌شده | تعداد ردیف درست؟ |
|---|---|---|---|
| | | | |
| | | | |
| | | | |

# تست ۳.۴ — چاپ باید حساس باشد

```sql
SELECT ACTION, SEVERITY, COUNT(*) AS تعداد
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID > <شروع_فاز۳>
GROUP BY ACTION, SEVERITY ORDER BY ACTION;
```

در فرم سوابق، تیک **«فقط موارد حساس»** را بزن و جستجو کن.

**انتظار:** چاپ و خروجی در نتیجه بیایند، ولی پیش‌نمایش نه.
