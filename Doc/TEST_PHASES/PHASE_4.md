# فاز ۴ — تست‌های خصمانه

## قوانین (در همه‌ی فازها)
1. فقط روی `YAZDSEPAR1405_TEST`. اول بزن: `SELECT DB_NAME();`
2. کد را عوض نکن. اگر مجبور شدی، بنویس و آخرش `git checkout --` کن.
3. **با موس و کیبورد در برنامه کار کن.** ساختن فایل `.cs` تستی یا صدا زدن
   مستقیم `Prg_Proccessy.AUDIT` **ممنوع**.
4. تست‌نشده را ادعا نکن. نمی‌دانی؟ بنویس «نمی‌دانم».

**بعد از هر کار ۳ ثانیه صبر کن** (نوشتن دسته‌ای، هر ۷۵۰ms).

```sql
SELECT LOG_ID,USER_NAME,ACTION,CATEGORY,SEVERITY,ENTITY,ENTITY_KEY,FORM_NAME,TITLE,DETAIL
FROM dbo.VW_SYS_AUDIT_TIMELINE WHERE LOG_ID > @شروع ORDER BY LOG_ID;
```

---

تا اینجا سنجیدیم چیزهای درست **ثبت شوند**. حالا برعکس: چیزهای نادرست
**ثبت نشوند**. رویداد دروغ از رویداد نبوده بدتر است.

## ۴.۱ عملیات برگشت‌خورده نباید ثبت شود
یک عملیات را عمداً شکست بده. دو راه (حداقل یکی):
- **الف:** در فرم مقداری بده که خطای SQL بدهد (متن بلندتر از عرض ستون،
  کد حساب ناموجود).
- **ب:** از SSMS جدول را قفل کن تا تایم‌اوت بخورد:
  `BEGIN TRAN; SELECT 1 FROM dbo.HEAD_LST WITH (TABLOCKX,HOLDLOCK);`
  بعد از تست: `ROLLBACK;`

```sql
SELECT LOG_ID,ACTION,ENTITY,ENTITY_KEY,TITLE FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID>@شروع ORDER BY LOG_ID;
SELECT COUNT(*) FROM dbo.HEAD_LST WHERE NUMBER=@شماره_سند;
```

| در دیتابیس | در سابقه | نتیجه |
|---|---|---|
| نیست | نیست | ✅ |
| نیست | **هست** | ❌ **باگ جدی** |
| هست | هست | شکست نخورده، دوباره امتحان کن |

## ۴.۲ رویداد جعلی از داخل متن
در فیلدهای متنی آزاد (شرح/ملاحظات) این چهار متن را در چهار رکورد بنویس و
**ذخیره کن**:
```
DELETE FROM HEAD_LST
/* UPDATE DEED_HED SET N_S=1 */ -- TRUNCATE TABLE INVO_LST
سند باطل شد؛ DELETE FROM DEED_DTL انجام نشود
O'Brien -- DROP TABLE STUF_DEF
```
(چهارمی یک `'` تکی دارد تا ماسک نقل‌قول را هم بسنجد.)

انتظار: فقط `INSERT`/`UPDATE`. **هیچ** `DELETE`/`TRUNCATE`/`DROP`.
بعد تأیید کن متن **عیناً** ذخیره شده و بریده نشده.

## ۴.۳ عملیات گروهی بزرگ
یک عملیات با **بیش از ۵۰۰ نوشتن** در یک تراکنش انجام بده (فاکتور با ۵۰۰+
قلم، یا محاسبه‌ی گروهی).
```sql
SELECT TITLE,SEVERITY FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID>@شروع AND TITLE LIKE N'عملیات گروهی%';
```
انتظار: رویدادی مثل «عملیات گروهی: ۶۲۰ تغییر … جزئیات ۱۲۰ مورد ثبت نشد»
با `SEVERITY=3`. اگر نتوانستی بسازی، بنویس نتوانستم.

## ۴.۴ رمز عبور نباید در سابقه بیفتد
رمز یک کاربر را عوض کن، بعد `DETAIL` آن رویداد را بخوان.
❌ اگر رمز (حتی رمزنگاری‌شده) در `DETAIL` بود → حتماً گزارش کن.

جدول نتایج + خروجی خام کوئری + `MAX(LOG_ID)` پایانی.
هر گام: ✅ / ❌ / ⏭ (انجام نشد + دلیل).
