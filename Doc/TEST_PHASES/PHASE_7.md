# تست ۷.۱ — جدول‌های قدیمی هنوز پر می‌شوند؟

قرار بوده `AMALIAT` و `USER_AUDIT_LOG` حذف **نشوند** و همچنان پر شوند —
فقط دیگر روی نخ رابط کاربری نوشته نشوند.

در برنامه یک فرم باز کن و یک رکورد حذف کن، ۳ ثانیه صبر کن:

```sql
SELECT TOP 5 * FROM dbo.AMALIAT ORDER BY ADATE DESC;
SELECT TOP 5 * FROM dbo.USER_AUDIT_LOG ORDER BY ActionDateTime DESC;
```

**انتظار:** کارهای همین الانِ تو در هر دو دیده شوند.

بعد تأیید کن همان رویدادها در جریان جدید هم هستند (نوشتن دوگانه):

```sql
SELECT TOP 5 LOG_ID, ACTION, ENTITY, TITLE
FROM dbo.VW_SYS_AUDIT_TIMELINE WHERE LOG_ID > <شروع_فاز۷> ORDER BY LOG_ID DESC;
```

# تست ۷.۲ — انتقال سابقه‌ی قدیمی

```sql
SELECT COUNT(*) AS قبل     FROM dbo.SYS_AUDIT_EVENT;
SELECT COUNT(*) AS amaliat FROM dbo.AMALIAT;
SELECT COUNT(*) AS userlog FROM dbo.USER_AUDIT_LOG;
```

حالا اجرا کن و **زمان بگیر**:

```sql
EXEC dbo.SYS_AUDIT_BACKFILL;
```

```sql
SELECT COUNT(*) AS بعد FROM dbo.SYS_AUDIT_EVENT;
```

**انتظار:** `بعد` ≈ `قبل + amaliat + userlog`.

اگر خیلی کمتر بود، انتقال ناقص انجام شده — گزارش کن.

**حین اجرا** از یک پنجره‌ی SSMS دیگر ببین جدول قفل طولانی می‌شود یا نه:

```sql
EXEC sp_who2;
```

انتقال باید **تکه‌تکه** (۲۰٬۰۰۰تایی) باشد تا لاگ تراکنش باد نکند و جدول
مدت طولانی قفل نماند.

| | مقدار |
|---|---|
| قبل | |
| `AMALIAT` | |
| `USER_AUDIT_LOG` | |
| بعد | |
| زمان اجرا | |
| قفل طولانی دیدی؟ | |

# تست ۷.۳ — ⭐ اجرای دوباره نباید تکراری بسازد

**این مهم‌ترین تست این فاز است.**

```sql
EXEC dbo.SYS_AUDIT_BACKFILL;
SELECT COUNT(*) AS بعد_از_دوبار FROM dbo.SYS_AUDIT_EVENT;

EXEC dbo.SYS_AUDIT_BACKFILL;
SELECT COUNT(*) AS بعد_از_سه‌بار FROM dbo.SYS_AUDIT_EVENT;
```

**انتظار: هر سه عدد دقیقاً یکی باشند.**

❌ اگر عدد بالا رفت، یک باگ جدی برگشته. این رویه در مسیر لاگین است و اگر
گاردش کار نکند، **هر بار بالا آمدن برنامه کل جدول را از نو درج می‌کند**.

> این دقیقاً باگی بود که یک بار وجود داشت: گارد قبلی دنبال
> `ACTION = 'DELETE'` می‌گشت و اگر جدول قدیمی هیچ ردیف `DELETE`ای نداشت،
> شرط هرگز برقرار نمی‌شد.

# تست ۷.۴ — پاک‌سازی

اول عکس فعلی را بگیر:

```sql
SELECT CATEGORY, COUNT(*) AS تعداد FROM dbo.SYS_AUDIT_EVENT GROUP BY CATEGORY;
SELECT COUNT(*) AS حذف‌ها FROM dbo.SYS_AUDIT_EVENT WHERE ACTION = 'DELETE';
```

حالا **زمان بگیر** و اجرا کن:

```sql
EXEC dbo.SYS_AUDIT_PURGE @KeepDaysNavigation = 90,
                         @KeepDaysOther      = 1825,
                         @ChunkSize          = 5000;
```

بعد:

```sql
SELECT CATEGORY, COUNT(*) AS تعداد FROM dbo.SYS_AUDIT_EVENT GROUP BY CATEGORY;
SELECT COUNT(*) AS حذف‌های_باقی‌مانده FROM dbo.SYS_AUDIT_EVENT WHERE ACTION = 'DELETE';
```

**انتظار:**
- ناوبری (`CATEGORY = 1`) قدیمی‌تر از ۹۰ روز **حذف** شود.
- ناوبری تازه‌تر از ۹۰ روز **بماند**.
- حذف و امضا (دسته‌ی ۲ و ۳) که کمتر از ۵ سال دارند **بمانند**.
- رویدادهای **امروز** — مخصوصاً کارهای همین تست — دست‌نخورده بمانند.

❌ **اگر رویداد حذفِ تازه پاک شده، باگ جدی است.**

**حین اجرا** با `sp_who2` ببین قفل طولانی می‌شود یا نه.

بعدش مطمئن شو کارهای فازهای قبلی هنوز هستند:

```sql
SELECT COUNT(*) FROM dbo.SYS_AUDIT_EVENT WHERE AT_SERVER >= CAST(GETDATE() AS DATE);
```

# تست ۷.۵ — جستجوی نقاط بی‌سابقه

سه مورد زیر **باگ نیستند**، محدودیت شناخته‌شده‌اند. فقط تأییدشان کن:

1. `AUTO_BAZ` در حالت اجرای مستقل هیچ موتور سابقه‌ای ندارد.
2. `WIN_F_NEWYEAR` (ساخت سال مالی، `BACKUP`/`RESTORE`/`CREATE DATABASE`)
   سابقه نمی‌خورد.
3. مقدار «قبل» فیلدها ثبت نمی‌شود — فقط مقدار جدید. (برای مقدار قبل،
   جدول‌های `TR_*` سر جایشان هستند.)
4. رویدادهای منتقل‌شده از دیسک به `AMALIAT`/`USER_AUDIT_LOG` نمی‌روند.

### ⭐ و سؤال اصلی این فاز

**در تمام هفت فاز، آیا جایی دیدی که کار مهمی انجام می‌شود ولی در سابقه
نمی‌آید؟**

برای جواب دادن، حداقل **پنج فرم دیگر** که تا حالا باز نکرده‌ای را امتحان
کن — ترجیحاً از حوزه‌های مختلف:

- یک فرم حسابداری (سند، دفتر)
- یک فرم انبار (رسید، حواله)
- یک فرم چک
- یک فرم تعاریف پایه (کالا، مشتری)
- یک فرم حقوق و دستمزد

در هر کدام یک رکورد **ثبت، ویرایش و حذف** کن و ببین سه رویداد می‌آید یا نه.

| فرم | ثبت | ویرایش | حذف | توضیح |
|---|---|---|---|---|
| | | | | |
| | | | | |
| | | | | |
| | | | | |
| | | | | |

❌ هر فرمی که رکورد عوض می‌کند ولی ردیفی نمی‌سازد، **یافته‌ی مهمی است** —
دقیقاً بنویس کدام فرم و چه کاری.

## ه) نظر نهایی

1. آیا این ماژول آماده‌ی استفاده روی دیتابیس عملیاتی است؟

3. اگر بله، چه چیزی را باید بعد از استقرار زیر نظر داشت؟
