# فاز ۶ — کارایی، حافظه و عدم تداخل با کار کاربر

**فاز ۶ از ۸.**

پنج قید اصلی این پروژه این‌ها بودند: سرعت، نشتی حافظه، امنیت، همزمانی، و
**«در کار کاربر نباید تداخلی ایجاد بشه یا باعث کندی بشه»**. این فاز
آخری‌ها را با **کرنومتر** می‌سنجد، نه با حدس.

---

## ⛔ یادآوری

1. فقط روی `YAZDSEPAR1405_TEST`. تأیید: `SELECT DB_NAME();`
2. کد را عوض نکن.
3. ⭐ با دست کار کن. اندازه‌گیری باید روی **کار واقعی کاربر** باشد، نه یک
   حلقه‌ی برنامه‌نویسی که متد را هزار بار صدا می‌زند.
4. حدس نزن، دروغ نگو. عدد بده، نه «سریع بود».

```sql
SELECT MAX(LOG_ID) AS شروع_فاز۶ FROM dbo.SYS_AUDIT_EVENT;
```

# تست ۶.۱ — کندی محسوس در کار واقعی

### مقایسه‌ی پایه — اگر می‌توانی

اگر یک بیلد **قدیمی‌تر بدون ماژول سابقه** در دسترس داری، همین چهار کار را
با آن هم انجام بده و دو ستون را کنار هم بگذار. این تنها راه اثبات
«کند نشده» است.

اگر نمی‌توانی، **بنویس «مقایسه‌ی پایه نداشتم»** و فقط عددهای فعلی را بده.
ننویس «کند نشد» — چون بدون مبنا نمی‌شود این را گفت.

# تست ۶.۲ — نشتی حافظه (نیم‌ساعته)

**این تست به دو عدد نیاز دارد، نه یکی.** دور قبل فقط یک عدد داده شد و
عملاً انجام نشد.

1. برنامه را تازه باز کن، وارد شو.
2. در Task Manager مصرف حافظه‌ی `MrCorrect.exe` را یادداشت کن → **عدد A**
3. **نیم ساعت کار عادی** بکن: فرم باز کن، سند ثبت کن، ویرایش کن، گزارش
   بگیر. کم‌کاری نکن — باید رویداد تولید شود.
4. دوباره یادداشت کن → **عدد B**

```
عدد A (شروع)      : ... MB
عدد B (بعد ۳۰ دقیقه): ... MB
اختلاف            : ... MB
چند رویداد ثبت شد : <از کوئری زیر>
```

```sql
SELECT COUNT(*) FROM dbo.SYS_AUDIT_EVENT WHERE LOG_ID > <شروع_فاز۶>;
```

**انتظار:** رشد حافظه باید کم و پایدار باشد. صف کران‌دار است (۲۰٬۰۰۰
رویداد) پس حتی با دیتابیس قطع نباید بی‌نهایت رشد کند.

### نسخه‌ی سخت‌تر (اختیاری ولی ارزشمند)

همین کار را با **دیتابیس قطع** تکرار کن: سرویس SQL را متوقف کن و ده دقیقه
در برنامه کار کن، و رشد حافظه را ببین. اینجاست که اگر صف کران‌دار نبود،
حافظه می‌ترکید.

# تست ۶.۳ — آیا رویدادی گم شده؟

```sql
SELECT SESSION_ID, USER_NAME, STARTED_AT, EVENT_COUNT, DROPPED_COUNT
FROM dbo.SYS_AUDIT_SESSION ORDER BY STARTED_AT DESC;
```

**انتظار:** `DROPPED_COUNT` صفر.

اگر صفر نیست: بنویس در کدام نشست، چه عددی، و **با چه کاری** پر شد. (این
شمارنده فقط وقتی بالا می‌رود که صف پر شود یا سقف فایل‌های دیسک تمام شود.)

فرم سوابق را هم باز کن — اگر رویدادی گم شده باشد، پایین فرم به تو هشدار
می‌دهد. اسکرین‌شات بگیر.

# تست ۶.۵ — همزمانی چند کاربر

**اگر می‌توانی:** برنامه را روی **دو کامپیوتر** (یا دو نشست Remote Desktop)
هم‌زمان با **دو کاربر مختلف** اجرا کن و هم‌زمان کار کنید.

```sql
SELECT USER_NAME, MACHINE_NAME, CLIENT_IP, COUNT(*) AS تعداد
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID > <شروع_فاز۶>
GROUP BY USER_NAME, MACHINE_NAME, CLIENT_IP;
```

**انتظار:** رویدادهای هر کاربر با نام کامپیوتر و IP **خودش** ثبت شود و
قاطی نشوند.

بعد بررسی کن `SEQ` در هر نشست یکتا مانده:

```sql
SELECT SESSION_ID, COUNT(*) AS کل, COUNT(DISTINCT SEQ) AS یکتا
FROM dbo.SYS_AUDIT_EVENT
WHERE LOG_ID > <شروع_فاز۶> AND SESSION_ID IS NOT NULL
GROUP BY SESSION_ID;
```

**انتظار:** `کل` و `یکتا` برابر باشند.

اگر فقط یک کامپیوتر داری، بنویس «نتوانستم» و رد شو.
