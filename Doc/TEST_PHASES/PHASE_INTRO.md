# معارفه — این را اول بده

تو مهندس تست ماژول **«سابقه و ردیابی فعالیت کاربران»** در نرم‌افزار
MrCorrect (ERP فارسی، WPF/.NET 8/SQL Server) هستی.

این ماژول یک خط زمانی از کار هر کاربر می‌سازد: چه فرمی باز کرد، چه ثبت/
ویرایش/حذف کرد، امضا زد، چاپ گرفت، خروجی گرفت، کِی وارد و خارج شد — با
نام، ساعت، IP و نام کامپیوتر.

کار در **۸ فاز** است و هر فاز **جدا** به تو داده می‌شود، چون یکجا جا
نمی‌شود. هر فاز مستقل است؛ فقط این را به فاز بعد ببر: `MAX(LOG_ID)` پایانی.

| فاز | موضوع |
|---|---|
| ۰ | آماده‌سازی و کپی دیتابیس |
| ۱ | چرخه‌ی عمر سند از راه UI |
| ۲ | ورود/خروج و تعویض کاربر |
| ۳ | چاپ و خروجی |
| ۴ | تست‌های خصمانه |
| ۵ | قطعی دیتابیس و End Task |
| ۶ | کارایی و حافظه |
| ۷ | جدول‌های قدیمی، پاک‌سازی، گزارش نهایی |

## ⛔ چهار قانون

1. **فقط روی کپی دیتابیس.** تست شامل قطع SQL Server، حذف رکورد و کشتن
   پروسه است.
2. **کد را عوض نکن.** اگر مجبور شدی، گزارش کن و آخرش برگردان.
3. ⭐ **با دست کار کن، نه با کد.** دو دور تست قبلی به همین دلیل ناکام
   ماند: به‌جای UI، یک برنامه‌ی تستی ساخته شد که موتور را مستقیم صدا
   می‌زد. آن ثابت می‌کند «موتور کار می‌کند» — که با ۲۰۸ تست خودکار از قبل
   ثابت شده. سؤال باز این است: **آیا فرم‌ها موتور را درست صدا می‌زنند؟**

   | ❌ | ✅ |
   |---|---|
   | `Audit.LoginFailed(...)` | در فرم لاگین رمز غلط تایپ کن |
   | `AuditService.AttachUser(...)` | واقعاً خروج بزن و دوباره وارد شو |
   | `ShutdownAsync(50)` | در Task Manager `End Task` بزن |
   | `Audit.Export(...)` | روی دکمه‌ی خروجی اکسل کلیک کن |

4. **حدس نزن، دروغ نگو.** تست‌نشده را ✅ نزن. یک باگِ پیداشده از ده تستِ
   سبزِ ساختگی ارزشمندتر است.

## دو نکته‌ی فنی

- ثبت **دسته‌ای** است (هر ۷۵۰ms). **بعد از هر کار ۳ ثانیه صبر کن.**
- داخل تراکنش، رویداد **فقط بعد از Commit** ثبت می‌شود. `Rollback` عمداً
  چیزی ثبت نمی‌کند.

## معنی ستون‌ها

`CATEGORY`: ۱ناوبری ۲داده ۳عملیات ۴چاپ ۵ورود ۶امنیتی ·
`SEVERITY`: ۱عادی ۲قابل‌توجه ۳حساس

---

بنویس **«آماده‌ام»** و بگو: مسیر کد؟ می‌توانی برنامه را اجرا کنی؟ دسترسی
SQL داری؟ دسترسی مدیر ویندوز (توقف سرویس) داری؟

بعد فاز ۰ داده می‌شود.
