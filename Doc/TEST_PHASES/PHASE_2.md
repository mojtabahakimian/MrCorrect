# فاز ۲ — ورود، خروج و تعویض کاربر از راه فرم واقعی

**فاز ۲ از ۸.**

این فاز یکی از سه سؤالی را جواب می‌دهد که دو دور تست قبلی نتوانستند:
**آیا خودِ فرم لاگین، نام کاربری تایپ‌شده را درست به سابقه می‌دهد؟**

در دورهای قبل این تست با فراخوانی مستقیم `Audit.LoginFailed(...)` انجام
شد — که فقط ثابت می‌کند موتور کار می‌کند، نه اینکه فرم لاگین درست صدایش
می‌زند.

---

## ⛔ یادآوری

1. فقط روی `YAZDSEPAR1405_TEST`. تأیید کن: `SELECT DB_NAME();`
2. کد را عوض نکن.
3. ⭐ **همه چیز با تایپ واقعی در فرم لاگین.** فراخوانی مستقیم
   `Audit.LoginFailed` یا `AuditService.AttachUser` **ممنوع**.
4. حدس نزن، دروغ نگو.

نقطه‌ی شروع را بگیر:

```sql
SELECT MAX(LOG_ID) AS شروع_فاز۲ FROM dbo.SYS_AUDIT_EVENT;
```

# تست ۲.۱ — ورود ناموفق

**چرا مهم است:** اگر تلاش ناموفق زیر نام کاربری ثبت شود که بعداً موفق
وارد شده، سابقه یک آدم بی‌گناه را متهم می‌کند.

**با دست انجام بده:**

1. از برنامه خارج شو (تا فرم لاگین بیاید).
2. نام کاربری **واقعی** خودت را تایپ کن، رمز **غلط** بزن. → خطا می‌گیری.
3. همین کار را **یک بار دیگر** تکرار کن.
4. نام کاربری‌ای که **اصلاً وجود ندارد** تایپ کن، مثلاً `nobody_xyz`، با
   هر رمزی. → خطا می‌گیری.
5. حالا با نام و رمز **درست** وارد شو.

۳ ثانیه صبر کن:

```sql
SELECT LOG_ID, AT_SERVER, USER_NAME, ACTION, TITLE, IS_SUCCESS
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID > <شروع_فاز۲> AND ACTION IN ('LOGIN','LOGIN_FAILED','LOGOUT')
ORDER BY LOG_ID;
```

**انتظار دقیق:**

| ردیف | `ACTION` | `USER_NAME` باید باشد | `IS_SUCCESS` |
|---|---|---|---|
| ۱ | `LOGOUT` | کاربر قبلی | True |
| ۲ و ۳ | `LOGIN_FAILED` | **نام کاربری واقعی که تایپ کردی** | False |
| ۴ | `LOGIN_FAILED` | **`nobody_xyz`** | False |
| ۵ | `LOGIN` | کاربر واقعی | True |

`TITLE` باید دلیل را هم بگوید — «رمز عبور نادرست» در برابر «نام کاربری
ناشناخته». این دو باید از هم **تفکیک** شده باشند.

❌ اگر `LOGIN_FAILED` زیر نام کاربرِ موفق ثبت شده، **باگ است**.
❌ اگر `USER_NAME` خالی (`NULL`) بود، **باگ است**.

# تست ۲.۲ — تعویض کاربر بدون بستن برنامه

**چرا مهم است:** اگر دو کاربر در یک نشست قاطی شوند، ردیابی بی‌معنی می‌شود.

**با دست انجام بده:**

1. با کاربر اول، **دو کار قابل‌ثبت** انجام بده (یک فرم باز کن، چیزی ویرایش
   کن). شماره‌ی `LOG_ID` را یادداشت کن.
2. **بدون بستن برنامه**، خروج بزن.
3. با یک **کاربر دیگر** وارد شو. (اگر کاربر دوم نداری، در `SALA_DTL` یکی
   بساز — ولی حواست باشد روی کپی هستی.)
4. با کاربر دوم **سه کار** انجام بده.

```sql
SELECT SESSION_ID, USER_ID, USER_NAME, STARTED_AT, ENDED_AT,
       EVENT_COUNT, DROPPED_COUNT
FROM dbo.SYS_AUDIT_SESSION ORDER BY STARTED_AT DESC;
```

**انتظار:**
- **دو نشست جدا** با `SESSION_ID` متفاوت.
- نشست کاربر اول `ENDED_AT` **پر** شده باشد.
- `STARTED_AT` نشست دوم از **لحظه‌ی ورود دوم** باشد، نه از ابتدای اجرای
  برنامه.

بعد تفکیک رویدادها:

```sql
SELECT USER_NAME, COUNT(*) AS تعداد,
       MIN(LOG_ID) AS از_, MAX(LOG_ID) AS تا_
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE LOG_ID > <شروع_فاز۲> GROUP BY USER_NAME;
```

**انتظار:** بازه‌ی `LOG_ID` دو کاربر **هم‌پوشانی نداشته باشد** — کارهای
کاربر دوم همه بعد از کارهای کاربر اول باشند.

❌ اگر کاری از کاربر دوم زیر نام کاربر اول ثبت شده، **باگ است**.

# تست ۲.۳ — ورود با رمز اصلی (اگر دارید)

اگر نرم‌افزار «رمز اصلی» یا master password دارد که با آن می‌شود به‌جای
کاربر وارد شد، یک بار با آن وارد شو.

**انتظار:** رویداد ثبت‌شده باید از ورود عادی **قابل تفکیک** باشد — عنوانش
باید بگوید ورود با رمز اصلی بوده.

اگر چنین قابلیتی ندارید یا نمی‌دانید، بنویس «نمی‌دانم» و رد شو.

# تست ۲.۴ — مشاهده‌ی خود سوابق ثبت می‌شود؟

فرم سوابق را باز کن و یک جستجو انجام بده.

```sql
SELECT TOP 5 LOG_ID, AT_SERVER, USER_NAME, ACTION, TITLE
FROM dbo.VW_SYS_AUDIT_TIMELINE
WHERE ACTION = 'AUDIT_VIEWED' ORDER BY LOG_ID DESC;
```

**انتظار:** یک رویداد `AUDIT_VIEWED` با دسته‌ی امنیتی (`CATEGORY = 6`).

> منطقش: کسی که سوابق بقیه را می‌بیند، خودش هم باید رد بگذارد.
