# فاز ۱ — چرخه‌ی عمر سند از راه UI

## قوانین (در همه‌ی فازها)
1. فقط روی `YAZDSEPAR1405_TEST`. اول بزن: `SELECT DB_NAME();`
2. کد را عوض نکن. اگر مجبور شدی، بنویس و آخرش `git checkout --` کن.
3. **با موس و کیبورد در برنامه کار کن.** ساختن فایل `.cs` تستی یا صدا زدن
   مستقیم `Prg_Proccessy.AUDIT` **ممنوع**.
4. تست‌نشده را ادعا نکن. نمی‌دانی؟ بنویس «نمی‌دانم».

**بعد از هر کار ۳ ثانیه صبر کن** (نوشتن دسته‌ای، هر ۷۵۰ms).

```sql
SELECT LOG_ID,USER_NAME,ACTION,CATEGORY,SEVERITY,ENTITY,ENTITY_KEY,FORM_NAME,TITLE,DETAIL
FROM dbo.VW_SYS_AUDIT_TIMELINE WHERE LOG_ID > @شروع ORDER BY LOG_ID;
```

---

مهم‌ترین فاز. یک پیش‌فاکتور واقعی بساز و **با موس و کیبورد** این کارها را
بکن. بعد از هر گام `MAX(LOG_ID)` را یادداشت کن.

| گام | کار | `ACTION` | دسته |
|---|---|---|---|
| ۱ | فرم پیش‌فاکتور را باز کن | `OPEN_FORM` | ۱ |
| ۲ | پیش‌فاکتور جدید با ۳ قلم ثبت کن | `INSERT` | ۲ |
| ۳ | مبلغ یک قلم را عوض کن و ذخیره کن | `UPDATE` | ۲ |
| ۴ | قلم چهارم اضافه کن | `INSERT` | ۲ |
| ۵ | یک قلم را حذف کن | `DELETE` | ۲ |
| ۶ | امضای اول را بزن | `SIGN` | ۳ |
| ۷ | امضای دوم را بزن | `SIGN` | ۳ |
| ۸ | امضای اول را بردار | `UNSIGN` | ۳ |
| ۹ | کل سند را حذف کن | `DELETE` | ۲ |

برای هر گام: ثبت شد؟ · `TITLE` فارسی خوانا؟ · `ENTITY_KEY` شماره‌ی سند
واقعی؟ · `FORM_NAME` درست؟ · برای `UPDATE`: `DETAIL` ستون تغییرکرده و
مقدار جدیدش را دارد؟

## سه نکته (این‌ها ایراد نیستند)
- **امضا:** یک کلیک همه‌ی خانه‌ها را با هم می‌نویسد، پس `DETAIL` وضعیت
  کامل را نشان می‌دهد. تغییر واقعی از مقایسه‌ی گام ۶→۷→۸ فهمیده می‌شود.
  انتظار: `1:بله 2:خیر` → `1:بله 2:بله` → `1:خیر 2:بله`
- **حذف سند ممکن است دو رویداد بسازد** (جدول قلم‌ها + جدول سر سند).
- **`FORM_NAME` یک زمینه است**، آخرین پنجره‌ی بازشده. مرجع دقیق،
  جدول و کلید خودِ رویداد است.

## اگر گام ۲ ممکن نشد
اگر نتوانستی سند جدید بسازی (گرید ردیف نمی‌دهد و…)، **وقت تلف نکن**:
بنویس نشد و چه کلیدهایی را امتحان کردی، و به‌جایش **یک سند موجود** را باز
کن و گام‌های ۳ و ۶ تا ۹ را روی آن انجام بده.

کامپیوتر، IP، کاربر ویندوز و JSON باید باز شوند. **اسکرین‌شات بگیر.**
